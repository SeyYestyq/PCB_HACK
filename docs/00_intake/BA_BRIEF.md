# BA Brief — ИИ-юридический ассистент ПСБ

> **Кейс:** Changellenge >> Hack&Change 2026 × ПСБ  
> **Дата:** 9 ноября 2026  
> **Статус:** intake (до дизайна и кода)

## 1. Проблема

Юристу банка нужно быстро найти применимые нормы во внутренней базе документов и **обосновать вывод ссылками**. Сейчас поиск и сопоставление источников съедают время, а «умный чат без контроля» опасен: LLM легко выдумывает законы.

## 2. Пользователи

| Роль | Задача | Ожидание |
|---|---|---|
| Юрист банка | Найти требования / основания (напр. правоспособность заёмщика) | Точный ответ + кликабельные фрагменты |
| Руководитель юр. подразделения | Проверить, на чём стоят выводы сотрудников | Прозрачные источники, явные отказы |

Оба умеют читать нормы. Им не нужен «дружелюбный GPT» — нужна **проверяемая выжимка**.

## 3. Что требует ТЗ (must)

1. Изучить выданную базу знаний (структура документов / положений).
2. RAG-поиск **только** по этой базе (внешние источники запрещены).
3. Ответ с **ссылками на конкретные положения**; юридические утверждения только из найденного.
4. Контроль достоверности:
   - недостаток информации → явный отказ + чего не хватает;
   - ошибка в вопросе → указать ошибку, не подстраиваться;
   - редакции / даты (доп. соглашения; для законов — только действующая редакция в базе);
   - не помогать в противоправном;
   - держать роль (jailbreak / поддельный system prompt).
5. Не галлюцинировать документы; не отказываться, если ответ в базе есть.
6. **Веб-чат** с просмотром документов и подтверждающих фрагментов.
7. Два контура сдачи: `solution.py` на автооценку LLM-судьёй + финальный Docker-прототип.

## 4. Как оценивают (на что бить)

Онлайн: **70% LLM-судья + 30% эксперты**.  
Веса экспертов: работоспособность 20% · контроль достоверности **25%** · архитектура/документы 20% · скорость 15% · UI 15% · презентация 5%.

Вывод: приоритет №1 — **качественный отказ/цитирование и score судьи**, UI — вторым, но без работающего чата к экспертам не допустят.

## 5. MVP-скоуп

- Ингест базы → чанки с метаданными (док, раздел, редакция/дата).
- Гибридный поиск (вектор + при необходимости full-text) + опциональный rerank.
- Пайплайн: retrieve → answer-with-citations → **verify/refuse** → UI.
- Чат: вопрос → ответ / отказ → сайдбар с фрагментами.
- `solution.py` совместим с регламентом (DeepSeek V4.1 Flash, embeddings BGE-M3, optional Qwen3 Reranker).

## 6. Не делаем в MVP

- Свои веса LLM / локальный train.
- Реальные внутренние нормы ПСБ (их нет в кейсе).
- Полноценная CMS/админка банка.
- Мультимодальность, голос, интеграции с АБС.

## 7. Риски

| Риск | Почему больно | Митигация |
|---|---|---|
| Галлюцинации ссылок | Юр. домен + критерии судьи | Пост-проверка: citation ∈ retrieved spans |
| Ложный отказ | База есть, бот отказал | Отдельные тесты «ответ должен быть» |
| Провал на jailbreak / off-topic | Явно в ТЗ | Классификатор намерения + жёсткий system policy |
| Расхождение online-бота и UI | Одна модель в регламенте | Общий core-сервис ответов для `solution.py` и веба |
| Нет данных кейса в репо пока | Приложение 1 — ссылка на папку | Заглушка индекса + чеклист «подключить базу организаторов» |

## 8. Вывод BA

Продукт — не «чат с ИИ», а **юридический retrieval с fail-closed ответом**.  
Победа = выше бейзлайна у судьи за счёт контроля достоверности + понятный чат с доказательствами.
