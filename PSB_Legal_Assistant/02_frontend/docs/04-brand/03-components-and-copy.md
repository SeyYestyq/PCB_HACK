# 03. Компоненты и тексты интерфейса

Каждый компонент описан по одной схеме:
**Назначение** → **Анатомия и размеры** → **Токены** → **Состояния** (default / hover / pressed / focus / disabled / loading / error) → **Доступность** → **Тексты** → **Почему так** (с источником).

Токены из `02-design-system.md`. Размеры в CSS px. «Зона нажатия» указана отдельно от визуального размера. Тексты без тире, без восклицательных знаков, без точки в конце подписей кнопок и бейджей (unslop Copy: «Trailing periods on labels and buttons → none»; HIG Writing: последовательные языковые шаблоны).

Основные нормы, на которые ссылаемся коротко:
- **HIG-B**: [Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons). «hit region of at least 44x44 pt»; «Always include a press state»; «Use style, not size, to visually distinguish the preferred choice»; «Don't assign the primary role to a button that performs a destructive action». Скриншоты `refs/02-apple-hig-buttons-anatomy.png`, `refs/03-apple-hig-buttons-hit-region-44pt.png`.
- **HIG-A**: [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility), таблица размеров `refs/01-...`.
- **HIG-L**: [Layout](https://developer.apple.com/design/human-interface-guidelines/layout), «Order content by relative importance», «Use progressive disclosure», «Differentiate controls from content». `refs/04-apple-hig-layout-visual-hierarchy.png`.
- **HIG-W**: [Writing](https://developer.apple.com/design/human-interface-guidelines/writing).
- **HIG-F**: [Feedback](https://developer.apple.com/design/human-interface-guidelines/feedback). «Show people when a command can't be carried out and help them understand why».
- **HIG-TF**: [Text fields](https://developer.apple.com/design/human-interface-guidelines/text-fields). «Show a hint in a text field», «match the size of a text field to the quantity of anticipated text».
- **HIG-LD**: [Loading](https://developer.apple.com/design/human-interface-guidelines/loading). «Show something as soon as possible», «Clearly communicate that content is loading».
- **HIG-LT**: [Lists and tables](https://developer.apple.com/design/human-interface-guidelines/lists-and-tables). «Provide appropriate feedback when people select a list item».
- **HIG-FS**: [Focus and selection](https://developer.apple.com/design/human-interface-guidelines/focus-and-selection). «Avoid changing focus without people's interaction».
- **HIG-AL**: [Alerts](https://developer.apple.com/design/human-interface-guidelines/alerts). «Avoid using an alert merely to provide information»; «If there's a destructive action, include a Cancel button».
- **WCAG**: [WCAG 2.2](https://www.w3.org/TR/WCAG22/).
- **NNG-RT**: [Response Times: The 3 Important Limits](https://www.nngroup.com/articles/response-times-3-important-limits/) (0.1 с, 1 с, 10 с).
- **NNG-ERR**: [Error-Message Guidelines](https://www.nngroup.com/articles/error-message-guidelines/).
- **NNG-PD**: [Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/).
- **NNG-CL**: [Minimize Cognitive Load](https://www.nngroup.com/articles/minimize-cognitive-load/).
- **FITTS**: [NN/g, Fitts's Law](https://www.nngroup.com/articles/fitts-law/).
- **HAX**: [Microsoft Guidelines for Human-AI Interaction](https://www.microsoft.com/en-us/haxtoolkit/ai-guidelines/); статья Amershi et al., CHI 2019, открыта 10.11.2026 [S-138].

## 1. Кнопки

### 1.1. Общая анатомия

HIG-B описывает кнопку как сочетание **стиля** (внешний вид), **содержимого** (подпись и/или символ) и **роли** (primary, normal, cancel, destructive). Мы фиксируем 4 стиля + icon-only.

```
┌──────────────────────────────┐  ← граница 1px (у secondary/destructive-secondary)
│ 16 │ [icon 20] 8 Подпись │ 16 │  ← высота 44 = 12 + 20 (line-height) + 12
└──────────────────────────────┘
```

| Параметр | L (по умолчанию) | M (плотная) |
|---|---|---|
| Высота визуальная | 44 | 32 |
| Зона нажатия | 44x44 минимум | 44 по высоте через `::before { inset:-6px 0 }`, если сосед не ближе 8; иначе 32 |
| Padding по горизонтали | 16 | 12 |
| Иконка | 20, обводка 1.5 | 16, обводка 1.5 |
| Зазор иконка ↔ текст | 8 | 8 |
| Шрифт | `type-control` 15/20, 500 | 14/20, 500 |
| Мин. ширина | 96 (кроме icon-only) | 64 |
| Радиус | 4 | 4 |
| Перенос подписи | Запрещён, `white-space: nowrap`; подпись короче 24 символов | |

Правила набора кнопок:
1. Не больше одной primary на экран или в одной группе действий. HIG-B: «use a button that has a prominent visual style for the most likely action in a view»; `refs/03` фиксирует ограничение в 1-2 заметных кнопки на вид.
2. Кнопки в группе одинаковой высоты; главная выделяется стилем, а не размером (HIG-B «Use style, not size»).
3. Порядок в группе слева направо: второстепенная, главная справа (конвенция macOS и веба; HIG-AL «Place buttons where people expect»).
4. Подпись всегда с глагола (HIG-W «it's almost always best to use a verb»).

### 1.2. Primary

**Назначение.** Единственное главное действие контекста: «Спросить» в композере, «Отправить уточнение» в форме уточнения, «Повторить» в системной ошибке.

| Состояние | Фон | Текст / иконка | Граница | Прочее |
|---|---|---|---|---|
| Default | `--color-accent` `#2B2C84` | `#FFFFFF` (11.69:1) | нет | |
| Hover | `--color-accent-hover` `#22236B` | `#FFFFFF` (13.81:1) | нет | переход `motion-fast` |
| Pressed | `--color-accent-pressed` `#1A1B55` | `#FFFFFF` | нет | без `transform` |
| Focus-visible | как Default | | `outline 2px #2B2C84`, `offset 2px` | зазор показывает фон, кольцо видно даже на синей кнопке |
| Disabled | `--color-surface-3` `#E6E6EF` | `--color-ink-disabled` `#8D8DA6` | нет | `disabled` или `aria-disabled` |
| Loading | `--color-accent` | Спиннер 16px белый + подпись стадии | нет | ширина зафиксирована по Default; `aria-busy` |

**Почему синий, а не оранжевый, как на сайте ПСБ.** Белый на `#E86630` даёт 3.29:1, на `#EA5614` 3.60:1, ниже 4.5:1 для текста 15px (WCAG 1.4.3). Синий 072C является основным цветом бренда по гайду и Depot. Оранжевая кнопка в юридическом инструменте читается как «срочно» или «опасно» и спорит с баннерами внимания.

### 1.3. Secondary

**Назначение.** Равноправные, но не главные действия: «Открыть документ», варианты ответа на уточнение («ООО «Альфа-Трейд»»), «Отмена» в диалоге.

| Состояние | Фон | Текст | Граница |
|---|---|---|---|
| Default | `--color-surface` | `--color-accent` (11.69:1) | 1px `--color-control-border` `#8D8DA6` (3.23:1, SC 1.4.11) |
| Hover | `--color-accent-tint` `#EDEDF7` | `--color-accent` (10.05:1) | 1px `--color-accent` |
| Pressed | `--color-evidence-bg` `#E4E4F3` | `--color-accent` | 1px `--color-accent` |
| Focus-visible | Default | | `outline 2px accent offset 2px` |
| Disabled | `--color-surface` | `--color-ink-disabled` | 1px `--color-line-strong` |
| Selected (для групп выбора) | `--color-accent-tint` | `--color-accent`, иконка `check` 16 слева | 1px `--color-accent`; `aria-pressed="true"` |

### 1.4. Ghost (tertiary)

**Назначение.** Частые второстепенные действия в строках, не требующие внимания: «Копировать ответ», «Показать все источники», «Свернуть».

| Состояние | Фон | Текст |
|---|---|---|
| Default | прозрачный | `--color-ink-2` `#5C5C73` (6.49:1) |
| Hover | `--color-surface-2` `#F0F0F7` | `--color-ink` |
| Pressed | `--color-surface-3` | `--color-ink` |
| Focus-visible | прозрачный | кольцо 2px accent |
| Disabled | прозрачный | `--color-ink-disabled` |

Ghost всегда имеет либо подпись, либо подпись в тултипе плюс `aria-label` (icon-only, см. 1.6). HIG-L: «Differentiate controls from content»: у ghost нет рамки, поэтому вокруг него 8px пустого поля минимум, а при визуальной высоте 32 зона нажатия расширяется до 44.

### 1.5. Destructive

**Назначение.** Только необратимое: «Очистить диалог» внутри диалога подтверждения. В ленте и в панели destructive-кнопок нет.

| Вариант | Default | Hover | Pressed | Focus | Disabled |
|---|---|---|---|---|---|
| Destructive-secondary (точка входа, в меню «…» диалога) | текст `--color-danger` `#BB3E45` (5.40:1), фон прозрачный | фон `--color-danger-bg` `#FBECEC`, текст danger (4.71:1) | фон `#F6DADB`, текст `--color-danger-hover` `#A1343A` (5.21:1) | кольцо 2px `--color-danger` | `ink-disabled` |
| Destructive-primary (в диалоге подтверждения) | фон `--color-danger`, текст белый | `--color-danger-hover` `#A1343A` | `--color-danger-pressed` `#8A2C31` | кольцо 2px danger, offset 2 | как Primary disabled |

Правило HIG-B: «Don't assign the primary role to a button that performs a destructive action». В диалоге фокус по умолчанию стоит на «Отмена», а не на «Очистить». HIG-AL: «If there's a destructive action, include a Cancel button». `Esc` закрывает диалог без действия.

### 1.6. Icon-only кнопка

| Параметр | Значение |
|---|---|
| Визуальный размер | 32x32 (M) или 44x44 (L, в композере) |
| Иконка | 20 |
| Зона нажатия | 44x44 (у M через `::before`), соседи не ближе 8 |
| Тултип | Обязателен, появляется через 500ms наведения или сразу при фокусе с клавиатуры; HIG-B: «the system displays a tooltip after people hover over a button for a moment» |
| `aria-label` | Совпадает с текстом тултипа |
| Состояния | Как ghost |

Использование icon-only разрешено только для универсально понятных действий: копировать, закрыть, свернуть панель, следующий/предыдущий фрагмент. HIG-B: «Consider using text when a short label communicates more clearly than an icon».

### 1.7. Ссылка (inline)

Текст `--color-accent`, подчёркивание 1px с `text-underline-offset: 3px`; hover: подчёркивание 2px; focus: кольцо 2px с радиусом 2. Подчёркивание обязательно, цвет не единственный признак (WCAG 1.4.1).

## 2. Композер

### 2.1. Назначение

Ввод вопроса или реплики в диалоге. Кейс: на вход поступает «одиночный вопрос либо история короткого диалога».

### 2.2. Анатомия

```
┌──────────────────────────────────────────────────────────────────────┐
│ 16 Вопрос по базе нормативных документов                          16 │  ← textarea, мин 1 строка
│                                                                      │
│ 16 Enter: отправить · Shift+Enter: новая строка        [ Спросить ] │  ← нижняя строка 44
└──────────────────────────────────────────────────────────────────────┘
   ↑ радиус 8, граница 1px #8D8DA6, фон #FFFFFF, тень уровня 1, max-width 680
```

| Часть | Размер | Токены |
|---|---|---|
| Контейнер | Ширина = колонка ленты (max 680), padding 12 16, радиус 8 | `surface`, граница `control-border`, тень 1 |
| Textarea | Высота от 24 (1 строка, 16/24) до 8 строк (192), далее внутренний скролл; общий мин. высота контейнера 44+ | `type-body` 16/24, `ink` |
| Плейсхолдер | «Вопрос по базе нормативных документов» | `ink-2` (6.49:1) |
| Подсказка клавиш | Слева в нижней строке | `type-meta` 13/18, `ink-3` |
| Кнопка «Спросить» | Primary L, 44 высота, мин. ширина 112, иконка `arrow-up` 20 слева от текста | Справа внизу |
| Отступ от края окна | 16 снизу, прилипает (`position: sticky`) | |

### 2.3. Тексты и почему

| ID | Текст | Почему |
|---|---|---|
| `composer.placeholder` | Вопрос по базе нормативных документов | HIG-TF «Show a hint in a text field»; определяет границу компетенции с первого взгляда (HAX G1 «Make clear what the system can do»). Не «Спросите что угодно» (unslop: «Wordy placeholders → Search»; «ask me anything» противоречит закрытой базе) |
| `composer.placeholder.followup` | Уточнение или следующий вопрос | После первого ответа: подсказывает, что контекст диалога сохраняется |
| `composer.hint` | Enter: отправить · Shift+Enter: новая строка | Юристы вставляют многострочные фрагменты договоров; без подсказки случайная отправка неочевидна |
| `composer.send` | Спросить | Глагол, короче «Отправить вопрос»; сохраняем из текущего `LegalChat.tsx` |
| `composer.stop` | Остановить | Появляется вместо «Спросить» во время ответа |
| `composer.label` (`aria-label`) | Вопрос по нормативным документам | Скринридер |
| `composer.limit` | Осталось 200 знаков | Показывается при остатке < 200 из 4000 |
| `composer.limit.over` | Вопрос длиннее 4000 знаков. Сократите его или разбейте на два | HIG-W «be clear about what someone can do to fix it» |

### 2.4. Состояния композера

| Состояние | Контейнер | Textarea | Кнопка |
|---|---|---|---|
| Пусто (default) | граница `control-border` | плейсхолдер | «Спросить» disabled; `aria-disabled`, тултип «Введите вопрос» |
| Hover | граница `ink-2` | | |
| Фокус в поле | граница 1px accent + кольцо 2px accent offset 0 (внутреннее кольцо, чтобы не прыгала раскладка). HIG-FS: «use a focus ring for a text or search field» | курсор | |
| Есть текст | | | «Спросить» enabled (primary) |
| Отправка / ответ формируется | граница `line-strong`; textarea `readonly`, текст сохранён | содержимое переносится в ленту, поле очищается | Кнопка меняется на Secondary L «Остановить» с иконкой `square` 16; ширина та же |
| Превышен лимит | граница 1px `danger` | | «Спросить» disabled; под контейнером строка `composer.limit.over` с иконкой `circle-alert`, цвет `danger`, `aria-describedby` |
| Ошибка сети после отправки | Текст вопроса возвращается в поле | | «Спросить» enabled |

**Почему кнопка «Спросить» справа внизу и 44px.** FITTS: время наведения зависит от расстояния и размера цели. Правый нижний угол композера ближе всего к концу набранного текста и к руке на мыши после набора; 44px высоты и 112 ширины делают цель крупной. HIG-B 44pt. Основной путь при этом клавиатурный (`Enter`), мышь вторична.

**Почему «Остановить» на месте «Спросить».** Одно место для управления текущим запросом, состояние читается из одной точки; HIG-B «Always include a press state» и HIG-F «Make sure all feedback is accessible».

## 3. Реплика пользователя

| Параметр | Значение |
|---|---|
| Выравнивание | По левому краю колонки, как и ответ. Не «пузырь справа» |
| Фон | `--color-surface-2` `#F0F0F7`, радиус 8, padding 12 16 |
| Текст | `type-body` 16/26 `ink`, сохраняются переносы строк |
| Подпись над репликой | «Вы» `type-meta` `ink-3`, время «22:41» справа |
| Ширина | 100% колонки (до 680) |

**Почему не пузыри мессенджера.** Сценарий не переписка с другом, а запрос и протокол ответа. Выравнивание по одной левой оси облегчает сканирование (HIG-L: «Align elements to make them easier to scan»). Референс `refs/16-pinterest-transcript-page-playbook.png`: реплики в одну колонку с метаданными.

## 4. Ответ ассистента

### 4.1. Анатомия (сверху вниз = по важности, HIG-L «Order content by relative importance»)

```
Ассистент · 22:41                                  [Копировать] [⋯]
[✓ Подтверждено базой]  4 источника

Вывод одним предложением, 17/24 600.                      ← type-headline
Обоснование абзацами 16/26 с чипами [1] [2] внутри
предложений.                                              ← type-body

┌ Чего не хватает (если есть) ───────────────────────────┐ ← баннер, раздел 8
└─────────────────────────────────────────────────────────┘

Основания                                                 ← type-label
[1] Регламент согласования договоров ред. 2025 · п. 2.2   → 56px строка
[2] Договор поставки П-17/2024 · п. 5.2                   → 56px строка
```

| Часть | Спецификация |
|---|---|
| Контейнер | Без фона и рамки (текст на `surface`), разделитель 1px `line` сверху между ходами; отступ между ходами 32 |
| Строка метаданных | Высота 32: «Ассистент» `type-meta` 500 `ink-2`, время `ink-3`; справа ghost M «Копировать» и icon M «⋯» |
| Бейдж статуса | Раздел 5. Стоит первым после метаданных, всегда |
| Счётчик источников | «4 источника» `type-meta` `ink-2`, кнопка-ссылка, открывает панель |
| Вывод | Первое предложение ответа, `type-headline`. Если API отдаёт сплошной текст, первое предложение выделяется на клиенте до первой точки, за которой пробел и заглавная буква |
| Тело | `type-body`, абзацы через 12, списки шагов нумерованные (кейс: «предлагать последовательность действий») |
| Основания | Раздел 7 |
| Действия в «⋯» | «Копировать с источниками», «Сообщить о неточности», «Очистить диалог» (destructive) |

Кейс: «не исправляет подтвержденные базой знаний ответы под давлением». Без извинений и без спора: позиция подкреплена ссылками |

### 4.3. «Как получен ответ» (трассировка, ТЗ SHOULD S5)

Открывается из меню «⋯» реплики (`trace.title`), в правой панели вместо списка источников, кнопка «← Источники» возвращает назад. Это режим для эксперта и руководителя, не для каждого ответа.

| Блок | Содержание (из полей `AnswerV2`) |
|---|---|
| Стадии | названия стадий и `timings_ms` таблицей, `tabular-nums` |
| Поиск | для каждой цитаты `scores` (ранг BM25, ранг dense, RRF, rerank) |
| Решение | статус, `reason`, сработавшие флаги (`premise_corrected`, `edition_applied`, `injection_ignored`, `pressure_resisted`, `degraded`) человеческими словами |
| Проверки | по каждому claim: цитата найдена в тексте, числа совпали, редакция применима (`claims[].checks`) |
| Служебное | `trace_id`, `prompt_version`, `kb_hash` (моноширинно, `type-meta`) |

Почему отдельный режим, а не всегда видимый блок: юристу нужен вывод и основание; внутренняя кухня нужна при проверке и на защите (критерии «Архитектура и работа с документами» и «Реализация контроля достоверности»). NNG-PD.

## 5. Бейдж статуса

### 5.1. Анатомия

Высота 24, padding 0 8, радиус 4, иконка 16 + зазор 4 + текст `type-label` 14/20 500. Фон тинт, текст и иконка статусного цвета. Не кликабелен; по наведению/фокусу (`tabindex="0"`) тултип с определением. Бейдж не прячется и не анимируется после появления.

Источник правды для полей: контракт `AnswerV2` в `../01-product/02-tz-complete.md` §3. Статусов пять; всё остальное выражается полем `reason` или флагом. Бейдж один на ответ, выбирается сверху вниз по таблице (первая совпавшая строка).

| `status=clarify` | Нужно уточнение | `circle-help` | `#2B2C84` / `#EDEDF7` (10.05:1) | Вопрос допускает несколько толкований. Уточните, чтобы поиск был однозначным |
| `status=limited` | Подтверждено частично | `circle-alert` | `#9A3A0E` / `#FDF0E9` (6.30:1) | Часть вывода подтверждена базой. Что не подтверждено, указано ниже |
| `status=grounded` | Подтверждено базой | `check` | `#4E621C` / `#EEF2E4` (5.98:1) | Каждое юридически значимое утверждение имеет ссылку на положение из базы знаний |

Флаги без собственного бейджа: `edition_applied` показывается в строке «Основания» («ред. 2023, утратила силу 01.03.2025», §7); `pressure_resisted` даёт строку `turn.pressureKept` под выводом (§4.2); `injection_ignored` виден в «Как получен ответ» (§4.3) и плашкой в просмотре документа (§10); `degraded` даёт баннер §8.9.

Пока ядро отдаёт контракт v1 (без `reason` и `flags`), работают только строки `grounded`, `limited`, `abstain` (как «Недостаточно данных»), `clarify`, `refuse_role` (как «Запрос отклонён») и клиентская ошибка.

**Почему так названы.** Метки описывают состояние доказательств, а не эмоцию и не уверенность модели. «Отказано, данных мало» из текущего кода заменено на «Недостаточно данных»: слово «отказано» звучит как административный отказ юристу, хотя отказывается не юрист, а ассистент от вывода. «Вне компетенции» для `refuse_role` разделено на «Запрос отклонён» и «Вне юридической тематики» по полю `reason`, потому что кейс разводит эти ситуации («Соответствие роли» и «непрофильные запросы», Огр. 10). «Ошибка в вопросе» стоит выше статуса доказательств, потому что исправление посылки юрист должен увидеть первым; сами основания при этом показываются как у обычного ответа.

**Почему без процента уверенности.** Числовая уверенность LLM не откалибрована и создаёт ложную точность; кейс требует решения «есть основания / нет оснований». HAX G2 требует показать, *насколько хорошо* система справляется: это делает статус + число источников + список недостающего. Lee & See 2004: калибровка доверия через видимые ограничения.

**Почему цвет + иконка + текст.** HIG Color: «Avoid relying solely on color»; WCAG 1.4.1.

**Доступность.** Бейдж в DOM идёт первым в реплике: `<p class="sr-only">Статус ответа:</p>` + текст. Скринридер услышит статус до содержания.

## 8. Баннеры исходов (fail-closed UX)

### 8.1. Общая анатомия

```
┃ [icon 20]  Заголовок, type-headline 17/24 600
┃            Пояснение, type-callout 14/20, 1-3 строки
┃            Список «Чего не хватает» / варианты / действия
┗━ полоса 4px слева статусного цвета; фон тинт; радиус 8; padding 16 20
```

Баннер стоит в теле ответа **вместо** или **после** вывода, никогда не во всплывающем окне. HIG-AL: «Avoid using an alert merely to provide information»; HIG-F: «Consider integrating status feedback into your interface». Референс `refs/17-pinterest-documentation-web-ui.png` (тинтованные callout-блоки в потоке текста); берём структуру, не фиолетовый цвет.

Баннеры не закрываются крестиком: это часть протокола ответа.

### 8.2. «Недостаточно данных» (`abstain`, `reason=insufficient` или `unverifiable`)

| Часть | Текст | Почему |
|---|---|---|
| Заголовок `banner.abstain.title` | В базе знаний нет оснований для достоверного ответа | Прямое заявление, как требует кейс («прямо сообщает»). Без «к сожалению» |
| Пояснение `banner.abstain.body` | Ассистент не делает выводов без подтверждающих положений | Объясняет политику (HAX G11 «Make clear why the system did what it did»). Снижает желание «дожать» |
| Подзаголовок списка | Чего не хватает | Кейс: «открыто указывает на то, какой информации не хватает» |
| Пункты | Из поля `missing[]`, например «релевантные документы по теме вопроса» | Конкретика вместо общего «данных мало» |
| Действие 1 (secondary M) | Переформулировать вопрос | Ставит фокус в композер с текстом вопроса |
| Действие 2 (ghost M, только при непустом `searched[]`) | Показать найденные фрагменты | Прогрессивное раскрытие: видно, что искалось (HAX G11). Фрагменты показываются серыми карточками с подписью «Не является основанием ответа», без чипов и без PT Serif-линии: по ТЗ у `abstain` нет цитат |

Цвет: полоса `--color-neutral-status`, фон `--color-neutral-bg`, иконка `circle-slash`. Почему не красный: `01`, раздел 5.2.

### 8.3. «Нет нужной редакции» (`abstain`, `reason=outdated_edition`; или `limited` + `flags.law_edition_warning`)

Пример (наш, не из демо-набора организаторов): «Какая ставка НДС применялась в 2019 году?». Ст. 164 НК РФ есть в базе только в действующей редакции (выгрузка 10.10.2026, п. 3: 22 процента), поэтому перенос этой ставки на 2019 год был бы неподтверждённым выводом.

| Часть | Текст |
|---|---|
| Заголовок | Для ответа нужна редакция нормы на дату события, её нет в базе |
| Пояснение | Законы в базе представлены только в действующей редакции. Ассистент не переносит действующую норму на прошлый период |
| Чего не хватает | «Редакция ст. 164 НК РФ, действовавшая в 2019 году» (из `missing[]`) |
| Действие | ghost M «Открыть действующую редакцию» (если статья есть в базе), подпись под кнопкой `type-meta`: «Справочно, не для вывода о прошлом периоде» |

### 8.4. «Подтверждено частично» (`limited`)

| Часть | Текст |
|---|---|
| Положение | Под выводом, перед «Основаниями» |
| Заголовок | Часть вывода не подтверждена базой |
| Пояснение | Подтверждённые утверждения отмечены ссылками. Утверждения без ссылки проверьте самостоятельно |
| Список | «Не подтверждено: ...» из `missing[]` |
| Визуально в тексте | Предложения без ссылки получают пунктирное подчёркивание 1px `--color-attention` и `title="Нет подтверждающего положения"` |

Полоса `--color-attention` (оранжевый 172C, единственное место бренда-акцента в ленте), текст `--color-attention-text`.

### 8.5. «Нужно уточнение» (`clarify`)

Пример: первая реплика диалога №17 из демо-набора, «Подскажите гарантию по договору с «Альфой»». В самом тесте №17 уточнение уже прозвучало в истории, и эталон отвечает по ПТ-05/2023 (см. `04` S7).

| Часть | Текст / вид |
|---|---|
| Заголовок | Уточните, о каком договоре речь |
| Пояснение | В базе два контрагента с похожими названиями. Без уточнения поиск будет неоднозначным |
| Варианты (secondary L, 44px, в ряд с переносом, зазор 8) | «ООО «Альфа-Трейд», договор П-17/2024» · «ООО «Альфа-Трейдинг», договор ПТ-05/2023» |
| Свободный ответ | ghost M «Ответить своими словами» (фокус в композер с плейсхолдером «Уточнение или следующий вопрос») |

Варианты формируются только из документов базы (поле `clarify.options[]` в `AnswerV2`, каждый вариант со своими claims); если их нет, показывается только текст и список `missing[]` («идентификатор договора или контрагента», «период / редакция»). Нажатие варианта отправляет его как реплику пользователя, кнопки ряда становятся disabled, выбранная получает состояние Selected.

Цвет: info (синий). Почему не оранжевый: уточнение не предупреждение, а следующий шаг. HIG-W: «Give clear guidance and use consistent language throughout processes with multiple steps». Кейс: «задавать уточняющие вопросы перед поиском ответа, если из запроса пользователя непонятно, о каком договоре, контрагенте или периоде идет речь».

### 8.6. «Ошибка в вопросе» (`flags.premise_corrected=true`)

Пример теста №4: «Почему по договору с ООО «Северный Склад» арендная плата 500 000 рублей в месяц?». В договоре А-08/2024, п. 3.1, сумма 450 000 рублей, включая НДС; эталон организаторов начинает ответ с этого исправления.

| Часть | Текст |
|---|---|
| Заголовок | В вопросе есть неточность |
| Тело | «Вопрос исходит из того, что [посылка]. По [документ, пункт] [как на самом деле] [1].» Шаблон заполняется API |
| Продолжение | Ниже идёт обычный ответ по данным базы с «Основаниями» (статус в API `grounded` или `limited`); бейдж остаётся «Ошибка в вопросе», статус доказательств виден в тултипе и в списке оснований |
| Действие | нет (не нужно подтверждение пользователя) |

Цвет: attention. **Почему твёрдая формулировка.** Кейс: «указывает на ошибку в запросе, и не "подстраивается" под пользователя». Формулировка «В вопросе есть неточность» не обвиняет человека (HIG-W «avoid blame»), но и не смягчает факт. Посылка всегда подкреплена ссылкой: юрист может проверить, кто прав.

### 8.7. «Запрос отклонён» (`refuse_role`)

| Подтип | Заголовок | Пояснение |
|---|---|---|
| `role_attack` (попытка сменить инструкции, поддельное «системное сообщение», просьба показать системный промпт; юридического вопроса в реплике нет) | Ассистент не меняет правила работы | Ответы строятся только по базе знаний. Задайте вопрос по документам базы |
| `illegal` | Ассистент не помогает обходить требования закона | Можно спросить, какие требования установлены и какие последствия предусмотрены. Ответ будет со ссылками на базу |

Давление на подтверждённый ответ («исправь, там 90 дней») сюда не относится: это не `refuse_role`, а обычный ответ с повтором цитаты и флагом `pressure_resisted` (§4.2, `04` F3). Если в реплике со сменой роли есть юридический вопрос, ассистент отвечает на него, а смену роли игнорирует (`flags.injection_ignored`).

Цвет: neutral, иконка `shield`. Действий нет, кроме ghost «Сообщить о неточности» в меню реплики. **Почему так.** Кейс: «не исправляет подтвержденные базой знаний ответы под давлением пользователя» и «не помогает совершать противоправные действия, но может разъяснять требования законодательства». Второе предложение показывает легитимный путь вместо глухого «нет» (HIG-F «help them understand why»).

### 8.8. «Вне юридической тематики» (`refuse_role`, `reason=off_topic`)

| Часть | Текст |
|---|---|
| Заголовок | Это вне юридической тематики |

## 11. Загрузка

### 11.1. Индикатор стадий в ленте

Появляется на месте будущего ответа через 0 ms после отправки (HIG-LD «Show something as soon as possible»).

| Время | Что показываем | Основание |
|---|---|---|
| 0-1 с | Метаданные «Ассистент» + строка стадии «Ищу положения в базе» со спиннером 16px | NNG-RT: 1 с предел непрерывности мысли |
| 1-10 с | Стадии сменяются по событиям API (или по таймеру, если API не стримит): «Ищу положения в базе» → «Сверяю ответ с найденными фрагментами» → «Проверяю ссылки». Панель источников показывает скелетон 3 карточек | HIG-LD «Clearly communicate that content is loading»; стадии объясняют, почему fail-closed занимает время (HAX G11) |
| > 10 с | Добавляется строка `type-meta`: «Ответ готовится дольше обычного. Можно остановить и уточнить вопрос» + кнопка «Остановить» уже в композере | NNG-RT: 10 с предел внимания |
| > 60 с (таймаут `LLM_TIMEOUT_SEC` в `pipeline.py`) | Переход в системную ошибку `timeout` | |

Тексты стадий без многоточий и без «Думаю...»: ассистент не «думает», он ищет и проверяет. Спиннер: кольцо 16px, обводка 2px `accent`, 800ms линейно; при `prefers-reduced-motion` статичная иконка `loader` и только текст.

Запрещено: «печатающиеся» точки, анимированные орбы, градиентный shimmer по тексту, фальшивый процент.

## 13. Системная ошибка

Отличие от отказа: ассистент не дал ответа по технической причине, а не по решению о достоверности.

| Код | Заголовок | Пояснение | Действия |
|---|---|---|---|
| `network` | Ответ не получен: нет соединения с сервисом ответов | Проверьте подключение. Текст вопроса возвращён в поле ввода | Primary L «Повторить» |
| `server` (5xx) | Ответ не получен: сервис ответов вернул ошибку | Попробуйте ещё раз через минуту. Если повторяется, сообщите администратору код {request_id} | Primary L «Повторить», ghost «Копировать код ошибки» |
| `timeout` | Ответ не получен за 60 секунд | Попробуйте сузить вопрос: укажите договор, контрагента или период | Primary L «Повторить», secondary «Изменить вопрос» |
| `validation` (пустой вопрос, 422) | (inline под композером) Введите вопрос | | |

Вид: баннер с полосой `danger`, фон `danger-bg`, иконка `triangle-alert`, `role="alert"`. Ровно на месте ответа в ленте (HIG-W «display it as close to the problem as possible»).

**Исправление текущего кода.** `LegalChat.tsx` показывает пользователю `err.message`, то есть до 200 символов сырого тела HTTP-ответа. Это нарушает NNG-ERR (сообщение на языке пользователя) и может раскрыть внутренние детали. Сырой текст уходит в консоль и в `request_id`, пользователю только тексты из таблицы.
