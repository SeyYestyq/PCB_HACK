## 1. Принципы разделения
1. **Разделение по контрактам, а не по слоям ради слоёв.** Три потока соединяются ровно тремя артефактами: `AnswerV2` JSON (ТЗ §3.3), `kb_manifest.json` + `units.jsonl` (модель данных, [`../02-architecture/03-data-model-and-kb.md`](../02-architecture/03-data-model-and-kb.md)), `eval/golden.jsonl` (ТЗ §9). Пока контракт не изменён через `DECISIONS.md`, потоки не блокируют друг друга.
2. **Один путь ответа** (M20): нет «веб-логики» и «сабмит-логики», есть ядро `psb_*.py`, которое вызывают `solution.py` и FastAPI.
3. **Достоверность раньше полировки** (из DECISIONS: credibility > retrieval quality > UI polish > pitch [K-INTAKE]).
4. **Командное владение** (5% защиты [K-PDF]): каждый умеет объяснить чужой поток на уровне одного абзаца и демо-сценария; это проверяется репетицией 19.11.

## 2. Календарь (рабочее допущение, не из кейса)
В PDF кейса [K-PDF] и в регламенте [K-REG] дат этапов нет: там формат сдачи, лимит 5 сабмитов в день со сбросом в 00:00 мск [K-REG §5] и правило фиксации версии после дедлайна. Даты ниже взяты из плана команды и **должны быть сверены с платформой Changellenge до 10.11**; при расхождении сроки всех задач пересчитываются.

## 7. Ритм работы
- 10:00 мск: 15-минутная синхронизация (вчера, сегодня, блокеры, какой сабмит и с какой гипотезой).
- До 18:00: изменения в `main` только через PR с зелёными тестами ядра; роль 3 ревьюит изменения промптов (они влияют на судью сильнее кода).
- 20:00-23:30: окно сабмитов (до сброса лимита в 00:00), чтобы не сжечь лимит утром на непроверенном.
- Правило фиксации: ни одна гипотеза не уходит в сабмит без прогона golden; результат публичного лидерборда сверяется с golden-прогнозом, расхождение > 0.05 разбирается.

## 8. Определение готовности (DoD) на 16.11
1. ZIP проходит smoke-тест в пустой папке; последний сабмит на лидерборде > 0 (условие допуска [K-PDF]).
2. `docker compose up --build` на чистой машине поднимает `answer` и `web`; основной сценарий проходит по README.
3. Все 18 демо-вопросов в UI: верный статус, цитаты открываются, подсветка совпадает.
4. Golden: метрики не хуже минимума ТЗ §1.
5. В репозитории нет секретов, нет реальных ПДн, нет наследия чужого продукта в сборке.
6. Презентация PDF с первым слайдом по требованиям.
