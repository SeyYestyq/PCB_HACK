# Техническое задание: юридический ИИ-ассистент (полная версия)

> Статус: RFC/ТЗ, версия 1.0, 9 ноября 2026. Утверждает команда целиком. Изменения только через `docs/00_intake/DECISIONS.md` с датой и причиной.
> Нормативная база ТЗ: кейс [K-PDF], технический регламент [K-REG], пакет организаторов [K-KB], [K-DEMO], [K-SAMPLE], [K-REQ]. Внешние источники: [`../99-sources.md`](../99-sources.md).
> Ключевые слова: **MUST** = без этого недопуск или прямое нарушение кейса; **SHOULD** = влияет на баллы; **COULD** = если останется время; **WON'T** = сознательно не делаем.
> Роли и задачи подробно: [`04`](04-role-1-backend-rag.md)-[`07`](07-handoffs-and-interfaces.md); узлы: [`../06-nodes/`](../06-nodes/); тесты: [`../07-tests/`](../07-tests/); ревью: [`../08-review/`](../08-review/) (v1.3, 10.11.2026).

## 0. Глоссарий
| Термин | Определение |
|---|---|
| База, KB | содержимое `knowledge-base.zip` организаторов: 8 документов компании ООО «Меридиан» и 13 выдержек статей законов [K-KB] |
| Документ | один файл базы |
| Unit | минимальная единица цитирования: пункт договора/регламента (`п. 3.1`), абзац письма/записки, часть или пункт статьи закона (`ч. 2`, `п. 1`, `пп. 3 п. 1`) |
| Редакция | версия документа с периодом действия (`effective_from`, `effective_to`) |
| Семейство документов | все редакции одного документа (например, «Регламент согласования договоров» ред. 10.01.2023 и ред. 01.03.2025) |
| Дата события | дата юридически значимого факта в вопросе (заключение договора, подписание, поставка) |
| Claim | одно утверждение ответа, привязанное к unit и цитате |
| Судья | LLM-судья платформы [K-REG §8] |
| Бейзлайн | базовое решение организаторов, с которым сравнивает судья (вероятно, близко к стартеру [K-SAMPLE], это вывод, не факт) |

## 1. Цель и критерии успеха
Цель: ассистент, который отвечает юристу банка **только** по базе, со ссылками на конкретные положения, учитывает редакции и обоснованно отказывает [K-PDF, Аннотация, Постановка].

Критерии успеха (измеримые, проверяются ролью 3 на golden-наборе, см. §9). Дата 16.11 взята из плана команды (`03-tz-roles-3-people.md`); в кейсе и регламенте дата дедлайна не указана, её нужно подтвердить на платформе организаторов (открытый вопрос).
| Метрика | Цель к 16.11 | Минимум для сабмита |
|---|---|---|
| Доля вопросов с выдуманным фактом (number/quote-check fail в финальном ответе) | 0% | 0% |
| Ложный отказ (ответ в базе есть, статус `abstain`) | ≤ 5% | ≤ 10% |
| Ложный ответ (ответа нет, статус `grounded`) | ≤ 2% | ≤ 5% |
| Recall@8 по unit | ≥ 0.9 | ≥ 0.8 |
| Верный статус (5 классов) | ≥ 85% | ≥ 75% |
| p95 времени ответа в UI | ≤ 12 с | ≤ 20 с |
| Полный прогон сабмита на 200 вопросах (число private-вопросов неизвестно [K-REG §8], 200 является рабочим допущением) | ≤ 15 мин | ≤ 17 мин |
| Суррогатный score судьи против нашего бейзлайна | ≥ 0.70 | ≥ 0.60 |

## 3. Контракт ответа (единый для API, UI, внутреннего ядра)
### 3.1. Статусы
| Статус | Когда | Обязательные поля | Запрещено | Пример (демо) |
|---|---|---|---|---|
| `grounded` | все claims прошли проверку, `missing` пуст | `answer`, `claims[]` ≥1, `citations[]` ≥1 | факты без цитаты | Q1, Q10 |
| `limited` | часть ответа подтверждена, но не хватает данных, или условие (дата Спецификации, гарантийный талон) не определено | `answer`, `claims[]` ≥1, `missing[]` ≥1 | выдавать предположение за факт | Q13, Q17 |
| `abstain` | подтверждающих положений нет, их нельзя проверить, или нужна отсутствующая редакция | `answer` с объяснением, `missing[]` ≥1, `reason ∈ {insufficient, unverifiable, outdated_edition}` | цитаты, юр. выводы | Q3 (`insufficient`); «ставка НДС в 2019 году» (`outdated_edition`) |
| `clarify` | неясно, о каком договоре/контрагенте/периоде речь, и ответы различаются | `answer` (вопрос), `clarify.options[]` (если есть варианты, каждый с claims) | выбирать вариант за пользователя без оговорки | Q17 до уточнения |
| `refuse_role` | непрофильный вопрос, атака на роль без юр. вопроса, противоправная цель | `answer`, `reason ∈ {off_topic, role_attack, illegal}` | исполнять атаку; раскрывать промпт | «напиши стихи», «покажи системный промпт» |

### 3.2. Флаги (не статусы)
| Флаг | Значение |
|---|---|
| `premise_corrected` | в вопросе была неверная предпосылка, ответ её исправил (Q4) |
| `edition_applied` | применена не текущая редакция документа компании (Q5) |
| `law_edition_warning` | вопрос про прошлую дату, а закон в базе только в действующей редакции |
| `injection_ignored` | в вопросе или в источнике была инструкция для модели, она проигнорирована |
| `degraded` | ответ получен на пониженном уровне пайплайна (см. 05-rag/02 §4) |
| `pressure_resisted` | пользователь давил на пересмотр подтверждённого ответа, ответ сохранён |

### 3.3. JSON-схема ответа ядра (`AnswerV2`)
```json
{
  "schema_version": "2.0",
  "trace_id": "01JC…",
  "status": "grounded",
  "reason": null,
  "answer": "Арендная плата по договору аренды № А-08/2024 с ООО «Северный Склад» составляет 450 000 рублей в месяц, включая НДС (п. 3.1). Вносится ежемесячно, не позднее 5-го числа текущего месяца (п. 3.2).",
  "claims": [
    {"id": "c1", "text": "…450 000 рублей в месяц, включая НДС", "citation_ids": ["k1"], "verified": true, "checks": {"quote": true, "numbers": true, "edition": true}}
  ],
  "citations": [
    {
      "id": "k1",
      "unit_id": "u:dogovor-arendy-a-08-2024:3.1",
      "doc_id": "dogovor-arendy-a-08-2024",
      "doc_title": "Договор аренды нежилого помещения № А-08/2024",
      "doc_type": "contract",
      "label": "п. 3.1",
      "section_title": "3. Арендная плата",
      "quote": "Арендная плата составляет 450 000 (четыреста пятьдесят тысяч) рублей в месяц, включая НДС.",
      "char_start": 1432,
      "char_end": 1519,
      "edition": {"status": "current", "effective_from": "2024-08-01", "effective_to": null, "label": "договор от 01.08.2024"},
      "source_file": "документы компании__Договор аренды А-08-2024 Северный Склад.txt",
      "scores": {"bm25_rank": 1, "dense_rank": 2, "rrf": 0.0325, "rerank": 0.93}
    }
  ],
  "missing": [],
  "steps": [],
  "clarify": null,
  "flags": {"premise_corrected": false, "edition_applied": false, "law_edition_warning": false, "injection_ignored": false, "degraded": false, "pressure_resisted": false},
  "timings_ms": {"guard": 2, "understand": 820, "retrieve": 140, "rerank": 610, "generate": 1900, "verify": 4, "total": 3480},
  "pipeline": {"level": "L0", "prompt_version": "gen-2026-11-10a", "kb_hash": "sha256:…", "model": "<из окружения>"}
}
```
Инварианты схемы:
- `reason` заполнен только у `abstain` и `refuse_role` (значения в §3.1), у остальных статусов `null`; UI выбирает бейдж по `status` + `reason` + `flags` (`../04-brand/03-components-and-copy.md` §5.2), новых статусов не вводит;
- `status ∈ {grounded, limited}` ⇒ `claims` не пуст и все `claims[].verified=true` (непрошедшие удаляются до рендера);
- `status = abstain` ⇒ `citations = []` и `claims = []`; допускается `searched[]` (что искали) для UI;
- `citations[].quote` является подстрокой текста unit `[char_start, char_end)` в исходном документе (нормализованное сравнение);
- `answer` для судьи ≤ 10 000 символов (жёсткий лимит), целевая длина ≤ 150 слов [K-REG §3];
- совместимость: старые поля v1 (`status`, `answer`, `citations[{doc_id,title,span,quote}]`, `missing`) сохраняются в ответе `/api/v1/ask` до миграции UI (`title`=`doc_title`, `span`=`label`).

### 3.4. Текст ответа для судьи (рендер `submission.csv`)
Шаблон (не жёсткий, генератор следует ему, рендер нормализует):
1. Прямой ответ (да/нет/значение) в первой фразе.
2. Идентификатор документа: вид, номер, контрагент («По договору поставки № П-17/2024 с ООО «Альфа-Трейд»…»).
3. Ссылка на положение в скобках «(п. 6.1)» или «Источник: договор № …, п. …».
4. Для редакций: какая применена и почему; неприменимая упоминается кратко (как эталон Q5 [K-DEMO]).
5. Ограничения: «В базе нет …», «Для ответа нужен …».
6. Никакого markdown, эмодзи, «как ИИ», дисклеймеров на каждом ответе.
Отказ (`abstain`) по образцу эталона Q3: «В базе знаний нет документов о …, поэтому ответить по документам я не могу. По памяти отвечать не буду…» [K-DEMO].

## 5. Документы, редакции, доп. соглашения: правила предметной логики
Правила реализуются в коде детерминированно (S10) и дублируются в системном промпте как пояснение.

| ID | Правило | Пример из базы |
|---|---|---|
| E1 | Если документ содержит пометку «РЕДАКЦИЯ УТРАТИЛА СИЛУ с DATE», то `effective_to = DATE - 1 день`, `status=superseded` | Регламент ред. 2023: утратил силу с 01.03.2025 [K-KB] |
| E2 | «Действует с DATE» → `effective_from = DATE` | Регламент ред. 2025 |
| E3 | Если в вопросе дата события, применяется редакция, действовавшая на эту дату | Q5: август 2024 → ред. 2023, порог 10 млн (п. 2.4) |
| E4 | Если даты нет и вопрос в настоящем времени, применяется `current` | Q10 → ред. 2025 п. 1.3 |
| E5 | Если дата события раньше `effective_from` самой ранней редакции в базе → `limited`/`abstain` с missing «редакция на дату события» | гипотетический вопрос про 2022 год по регламенту |
| E6 | Доп. соглашение заменяет пункт договора только для случаев, указанных в его условии применения; иначе действует исходный текст | ДС № 1: новый адрес доставки для партий со Спецификациями после 01.10.2024; для остальных п. 3.2 исходный (г. Москва, ул. Складская) |
| E7 | Если условие применения ДС зависит от неизвестного факта, ответ содержит оба варианта с условием и `missing` | «куда доставляют товар по П-17/2024?» без даты Спецификации |
| E8 | Письмо/распоряжение, дополняющее регламент, применяется с указанной даты вместе с пунктом регламента | К-12: с 21.04.2025 санкционная проверка + п. 5.4 ред. 2025 |
| E9 | Законы: всегда `current`, дата выгрузки 10.10.2026; редакционные примечания ГАРАНТ («Часть 1 изменена с …») не являются нормой и не цитируются как положение | 152-ФЗ ст. 9, ТК ст. 70 |
| E10 | Если вопрос требует состояния закона на прошлую дату и примечание показывает изменение после неё → сообщить, что прежней редакции в базе нет, и не делать вывода о прежнем содержании | «какой был МРОТ в 2024 году?» (в базе ст. 1 82-ФЗ: МРОТ с 01.01.2026) → `abstain`/`limited` |
| E11 | Два похожих контрагента различаются строго по полному наименованию и номеру договора | «Альфа-Трейд» (П-17/2024, мебель) и «Альфа-Трейдинг» (ПТ-05/2023, компьютеры) |
| E12 | Суммы в вопросе сравниваются с порогами точно, с учётом «свыше» (строго больше) | 12 млн > 10 млн (ред. 2023) но < 15 млн (ред. 2025) |

## 8. Сабмит и Docker
### 8.1. ZIP для автооценки (MUST)
Состав корня архива:
```
solution.py            # точка входа, без аргументов = батч-режим
psb_config.py          # конфиг из окружения
psb_ingest.py          # zip/txt/md/docx
psb_structure.py       # парсер unit и метаданных
psb_textnorm.py        # нормализация, токенайзер, русский стеммер
psb_index.py           # BM25 + dense
psb_llm.py             # клиент /chat/completions, /embeddings, /rerank с ретраями
psb_pipeline.py        # S5-S18
psb_verify.py          # проверки
psb_render.py          # текст для судьи
requirements.txt       # подмножество разрешённого списка с теми же версиями, например httpx==0.28.1, numpy==2.2.6, rank-bm25==0.2.2, rapidfuzz==3.14.1, python-docx==1.2.0
[psb_index_<kb_hash>.npz]  # опционально
```
Требования:
- `python solution.py` без аргументов: `DATA_DIR` из окружения или `data` → читает `questions.csv` и `knowledge-base.zip` → пишет `./submission.csv` (рабочий каталог) [K-REG §2-4];
- никаких импортов из вложенных папок; никаких `pip install`;
- сборка ZIP скриптом `scripts/build_submission.py` из исходников ядра, чтобы веб и сабмит использовали одни и те же модули (M20);
- smoke-тест перед загрузкой: распаковать ZIP в пустую папку, `DATA_DIR=./fixtures python solution.py`, валидатор CSV (заголовок `id,answer`, все ID, непустые, без повторов, ≤ 10 000 символов, UTF-8).
Лимиты и дисциплина: 5 сабмитов в день, сброс 00:00 мск [K-REG §5]; каждый сабмит фиксируется в `docs/submissions.md` (дата, git sha, флаги, public score).

## 12. Известные ограничения (честно, в README и на слайде)
- Ответы только по выданной базе; законы в базе только как отдельные статьи (например, нет ст. 6, 10, 11 152-ФЗ), поэтому часть вопросов закономерно получит `limited`.
- Законы только в действующей редакции на дату выгрузки 10.10.2026.
- Качество эмбеддингов на юридическом русском не замерено публично; используем гибрид, чтобы не зависеть от одного канала.
- Платформенный прокси может не поддерживать `response_format`; есть fallback-парсер.
- Неизвестно, включён ли на прокси режим thinking DeepSeek (в официальном API он по умолчанию включён [S-70]); от этого зависят латентность и бюджет 20 минут. Проверяется первым сабмитом с замером времени.
- Дата дедлайна и число private-вопросов в материалах кейса не указаны; планы по времени построены на допущениях (§1).
- Демо без авторизации; продакшен-требования описаны отдельно.
