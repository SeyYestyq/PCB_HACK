# Ревью и полный набор тестов

Здесь лежит полный комплект `docs/07-tests/` и `docs/08-review/`, без выборочного отбора. Те же файлы частично скопированы в папки ролей, но если нужна полная картина или ссылка из `INDEX.md` на тест или ревью, открывайте эту папку. Оригинальные относительные пути внутри `docs/` сохранены.

## Что читать и в каком порядке

1. Стратегия тестов: `docs/07-tests/00-strategy.md`.
2. Каскад: `docs/07-tests/01-cascade.md` (если упал тест: таблица «симптом → узел»).
3. Регрессия: `docs/07-tests/02-regression.md`.
4. Unit и контракт: `docs/07-tests/03-unit-and-contract.md`.
5. Golden и судья: `docs/07-tests/04-eval-golden.md`.
6. Трассировка: `docs/07-tests/05-traceability.md`.
7. Артефакт as-is: `docs/07-tests/artifacts/asis-d1f068c-lexical-run.md`.
8. Правила ревью: `docs/08-review/00-overview.md`, затем вид по случаю: `01` ядро, `02` фронт, `03` архитектура, `04` безопасность, `05` тесты и eval, `06` документация.

## Кто чем владеет

Тесты узлов ND1-ND7 и сабмита - роль 1. UI/a11y и контракт «поле API → экран» - роль 2. Golden, оракулы, формула судьи, трассировка - роль 3. Ревьюер читает нужный вид из `08-review/` и файл затронутого узла в `../03_backend_rag/docs/06-nodes/` или `../02_frontend/docs/06-nodes/08-frontend.md`.

Суммы каталогов на момент v1.6: 135 регрессионных, 118 unit, 24 контрактных, 63 каскадных, golden не меньше 135 по 19 типам. `RG-PERF-01` сознательно не заведён. `RG-A11Y-08` требует ручной проверки.

## Готово, когда

Для ревью PR: выполнены правила `00-overview.md` и чек-лист нужного вида, находки зафиксированы. Для тестового контура: соответствующие каталоги зелёные на согласованном коммите. Живой прогон модели, ручная a11y-проверка и замер производительности в эту папку не входят как уже закрытые пункты.
