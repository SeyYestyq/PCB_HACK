# 08.02. Ревью фронтенда и дизайна

> Версия 1.0, 10.11.2026. Узел: [`../06-nodes/08-frontend.md`](../06-nodes/08-frontend.md). Брендбук: [`../04-brand/`](../04-brand/); обоснования решений: [`../04-brand/07-decision-justifications.md`](../04-brand/07-decision-justifications.md). Общие правила: [`00-overview.md`](00-overview.md).

## 1. Зачем и кто
**Зачем.** Интерфейс является тем, что эксперт видит первым (Интерфейс и удобство 15%, основной сценарий как условие Работоспособности 20% [K-PDF]). В нашем продукте у UI есть ещё одна обязанность: **не обещать больше, чем проверено**. Пузырь собеседника, печатающиеся точки и посимвольная печать сообщают «ассистент пишет ответ», хотя ответа может не быть вовсе (fail-closed). Ревью фронта проверяет, что UI честен так же, как ядро.

**Кто.**
| Что в PR | Ревьюер | Почему |
|---|---|---|
| Любое изменение `apps/web` | роль 1 | потребление контракта, SSE, ошибки |
| Тексты, статусы, пустое состояние | роль 3 | тексты из `04-brand/03`, вопросы по реальной базе |
| Токены, сетка, типографика, движение | роль 3 как второй глаз по брендбуку; автор роль 2 отвечает за соответствие | брендбук писали все, но спорить с собой нельзя |

## 2. Когда
- Каждый PR в `apps/web`.
- Визуальное ревью на скриншотах трёх ширин (1440, 1024, 390) и на всех 11 фикстурах состояний: автор прикладывает их к PR.
- Ручная проверка доступности перед финальным сабмитом и перед защитой (WCAG-EM [S-134]).

## 3. Что смотреть и как
### 3.1. Контракт
- Тип из схемы, исчерпывающий `switch` по статусу; нет `| string` (as-is legal-api.ts 14, D21).
- В запросе есть `history` (as-is 24 без неё, D19).
- Ключи и якоря цитат по `citation.id` (as-is `doc_id` в LegalChat.tsx 103, 142, D23).
- Неизвестный статус рисуется нейтрально, не падает.

### 3.2. Статусы и честность
- Каждому статусу и `reason` своя отрисовка; тексты из `04-brand/03` §5.2. As-is ярлык `abstain` «Отказано, данных мало» (LegalChat.tsx 11-17) смешивает отказ и нехватку: `blocking`.
- Статус передан текстом, иконкой и цветом (WCAG 1.4.1 [S-115]). Проверка: скриншот в оттенках серого, статусы различимы.
- Ответ появляется целиком после проверки. Признаки нарушения в diff: таймер, добавляющий символы; компонент «typing»; анимация трёх точек; кнопка с «…» (as-is LegalChat.tsx 131). Это `blocking` по брендбуку (`04-brand/06` §12).
- Строка стадии использует только ключи `progress.*`; длительное ожидание даёт `progress.slow`, а не процент.

### 3.3. Сетка, форма, типографика
- Обе реплики по левому краю, радиус 8, без хвостика (as-is `.legal-bubble.user` с `align-self: flex-end` и `border-radius: 12px 12px 4px 12px`, globals.css 127-135: `blocking`).
- Радиусы только 2 / 4 / 8 / 12; 16 и больше и pill запрещены (as-is 28, 12, 10: globals.css 27, 123, около 226 и 247).
- Колонки 264 / 680 / 400 (as-is 280 в globals.css 75).
- Golos Text, PT Serif, запасной Verdana (as-is IBM Plex Sans / Source Serif 4, 28-29).
- `#2B2C84` primary (в CSS `#2C2D84`), `#EA5614` только полосы и маркеры (контраст 3,60:1 на белом, не для текста), никогда `#EF3124` (as-is globals.css 6 и тень 375).

### 3.4. Взаимодействие
- Поле при ответе `readonly`, не `disabled` (as-is 123); кнопка «Остановить»; защита от двойной отправки логикой, а не выключением кнопки [S-109].
- Клик по `[n]` ведёт к карточке, карточка к документу с подсветкой по офсетам; наведение и фокус на `[n]` показывают поповер с началом цитаты. Отдельного автотеста на этот путь нет, проверяется руками. Почему путь к пункту должен быть коротким: проверку цитаты пропускают, когда она дорога [S-151] (`04-brand/07` BJ-10).
- Дисклеймер `DISCLAIMER_SHORT` в футере под композером, вне прокручиваемой ленты: одноразовое предупреждение в ленте уезжает за край экрана [S-151].
- `clarify`-кнопки отправляют уточнение с историей.

### 3.5. Доступность
- `role="status"`, `aria-live="polite"` у строки стадии [S-101], [S-113].
- Фокус видим, порядок табуляции логичен.
- «Спросить» в пустом поле и при превышении 4000 знаков: `aria-disabled="true"`, а не атрибут `disabled` (иначе кнопка выпадает из порядка табуляции и скринридер её не находит [S-143]); клик гасится логикой, подсказка `composer.send.disabledTip` показывается и по фокусу с клавиатуры, без `pointer-events: none` [S-144]. Проверяется руками (RG-A11Y-08), автотеста нет.
- Движение ≤ 5 с без механизма остановки [S-114].
- axe в Playwright без critical/serious, но **автоматика находит не всё** [S-93]: ручная проверка клавиатурой и скринридером обязательна перед финалом.

### 3.6. Как смотреть
1. Скриншоты 11 состояний × 3 ширины рядом с макетом `04-brand/04`.
2. Запуск локально с фикстурами, пройти клавиатурой S0 → вопрос → ответ → источник → документ.
3. DevTools: computed styles радиусов, шрифтов, цветов на трёх элементах.
4. Только потом код.

## 4. На что влияет находка
| Находка | Уровень | Критерий |
|---|---|---|
| Статус не различим без цвета, UI падает на состоянии | `blocking` | Интерфейс 15%, доступность |
| Typing dots, посимвольная печать, пузырь справа, `#EF3124`, радиус ≥ 16 | `blocking` (брендовый запрет) | Интерфейс 15%, достоверность восприятия |
| Панель показывает не тот ответ | `blocking` | Достоверность 25% (юрист проверяет не то) |
| Отступ не по сетке на 2 px | `nit` | |

## 5. Как фиксировать
Как в [`00-overview.md`](00-overview.md) §3.3; визуальная находка содержит скриншот и ссылку на правило брендбука (файл, параграф). Находки, которые не исправлены, становятся строками D27 или новым D-номером.

## 6. Готово / не готово
Готово: 11 фикстур рендерятся (UT-UI-01..18), RG-UI-01..10 и RG-A11Y-01..07 зелёные, скриншоты приложены, тексты из `04-brand/03`.
Не готово: хотя бы один брендовый запрет; «доступность проверим потом»; новый текст статуса, не согласованный с ролью 3.

## 7. Частые ошибки ревьюера фронта
| Ошибка | Почему плохо | Как правильно |
|---|---|---|
| Смотреть только на «счастливый» ответ | 10 из 11 состояний не видны | все фикстуры |
| Доверять axe | автоматика пропускает многие проблемы [S-93] | ручной проход |
| Спорить о вкусе там, где есть правило | время | ссылка на брендбук или `nit` |
| Принимать «как в ChatGPT» как аргумент | у нас другая модель ответа: заключение, а не реплика; см. `04-brand/07` | обоснование из брендбука |
| Не проверять узкий экран | панель источников исчезает | ширина 390 |

## 8. Почему так
Ревью по правилам, а не по вкусу, потому что решения уже обоснованы и записаны в брендбуке с источниками ([`../04-brand/07-decision-justifications.md`](../04-brand/07-decision-justifications.md)). Ревьюер проверяет соответствие решению; несогласие с решением идёт отдельным предложением, а не блокировкой PR. Процедура ручной оценки доступности: W3C WAI [S-134].
