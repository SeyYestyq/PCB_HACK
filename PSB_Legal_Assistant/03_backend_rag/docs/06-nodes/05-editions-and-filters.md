## 1. Место в потоке
Между поиском (ND2 S9) и реранком/генерацией. Модель получает уже отобранные редакции: она не решает, какая редакция действовала в августе 2024 года.

**Инварианты.**
- I-ND5-1: при заданной `event_date` в контексте генерации не может оказаться редакция документа компании, не действовавшая на эту дату, кроме явного сравнения («изменился ли порог»), где обе редакции помечены.
- I-ND5-2: границы дат включительные и однозначные: регламент ред. 2023 действует по 28.02.2025 включительно (E1: «утратила силу с 01.03.2025»), ред. 2025 с 01.03.2025 включительно (E2).
- I-ND5-3: «свыше N» означает строго больше (E12): договор ровно на 3 000 000 рублей по ред. 2025 не требует финансового директора (п. 2.3).
- I-ND5-4: условие ДС «после 1 октября 2024 г.» строгое: Спецификация от 01.10.2024 даёт исходный адрес п. 3.2.
- I-ND5-5: законы всегда `current`; редакционные примечания ГАРАНТ не являются нормой (E9).

## 3. To-be спецификация
### 3.1. Семейства и интервалы
`doc_family` объединяет редакции одного документа («Регламент согласования договоров»). Для каждой редакции `[effective_from, effective_to]`, открытый конец у `current`. Интервалы семейства не пересекаются; тест `CT-B3-02` проверяет это на manifest.

### 3.2. Алгоритм на вопрос
```
если entities.event_date задана:
    для каждого семейства среди кандидатов:
        оставить редакцию R, где R.from ≤ event_date ≤ R.to (to открыт у current)
        если такой нет и event_date < min(from): missing += "редакция на дату события", статус-подсказка limited/abstain (E5)
иначе если вопрос сравнительный («изменился ли», «как было раньше»):
    оставить все редакции, пометить superseded_comparison
иначе:
    оставить current (E4)

для каждого кандидата-пункта договора с amended_by:
    условие ДС (applies_if) вычисляется по фактам вопроса
    если факт известен: оставить применимый текст (исходный или новый)
    если неизвестен: оставить оба, conditions[] += {если …, то …}, missing += "дата подписания Спецификации" (E6, E7)

для писем, дополняющих регламент (supplements): применить с даты письма вместе с пунктом (E8)

для законов: всегда current;
    если event_date < даты последнего изменения нужной части по editorial_note:
        law_edition_warning = true; missing += "редакция закона на дату события"
        если вывод без старой редакции невозможен: подсказка abstain(outdated_edition), иначе limited (E10)
```

### 3.3. Извлечение `event_date`
Даты событий («в августе 2024», «в мае 2025», «договор от 15.03.2025») извлекает S7 (ND4) в нормализованном виде (`2024-08`, `2025-05-15`); месяц без дня трактуется как интервал месяца. Если интервал пересекает границу редакций (событие «в марте 2025» при смене редакции 01.03.2025 эта граница не пересекается, а «в феврале-марте 2025» пересекается), ответ даёт оба варианта с условием, статус `limited`.

### 3.4. Чего узел не делает
Не угадывает год, если в вопросе его нет; не применяет «здравый смысл» о том, когда, вероятно, подписан договор. Отсутствие даты = настоящее время (E4) или `missing`, если вопрос явно о прошлом.

## 4. Почему так
1. **Явная версионная логика побеждает «умную модель».** VersionRAG на версионных вопросах: наивный RAG 58%, GraphRAG 64%, версионно-осознанный подход 90% [S-11]. SAT-Graph RAG формализует point-in-time retrieval для норм как детерминированный шаг [S-10].
2. **Кейс требует этого прямо.** Для документов компании применять редакцию на дату события с учётом доп. соглашений, а закон отвечать только по действующей редакции и говорить, если вопрос требует старой [K-PDF Постановка 04].
3. **Почему для закона важна дата договора, даже если в базе только действующая редакция.** По ГК РФ акты гражданского законодательства не имеют обратной силы, а к договору, заключённому до нового закона, применяется ст. 422 [S-146]: договор должен соответствовать императивным нормам, действовавшим в момент заключения, а новый закон распространяется на ранее заключённые договоры, только если это в нём прямо сказано [S-147]. Поэтому вопрос о договоре 2024 года, ответ на который зависит от закона, нельзя молча закрывать текущей редакцией: если в вопросе есть дата заключения раньше даты редакции закона в базе, это флаг `law_edition_warning` и `limited` (или `abstain(outdated_edition)`, если без старой редакции ответа нет), как и требует кейс; тест того же класса `RG-ED-LAW-01`. Сам узел ND5 юридических выводов о переходных положениях не делает: он только сравнивает даты и ставит флаг.
4. **Даты считает код, не модель.** Модели систематически ошибаются в деталях вроде дат; Apple HIG по генеративному ИИ отдельно предупреждает, что модели «sometimes get details wrong, like dates» [S-103]. Сравнение `≤`/`<` на границе 01.03.2025 является ровно такой деталью.
5. **Детерминизм воспроизводим.** Даже при temperature 0 ответы LLM API не детерминированы (в эксперименте Thinking Machines 1000 запусков при temperature 0 дали 80 разных завершений) [S-77]. Резолвер редакций на чистых функциях даёт один результат на любом прогоне, и его можно покрыть граничными unit-тестами.

## 5. Отвергнутые альтернативы
| Альтернатива | Почему нет |
|---|---|
| Подстроки годов (as-is) | ложные отказы на договорах с датами (D13), пропуск вопросов про 2024/2025 |
| Отдать все редакции модели с пометками | модель выбирает неверную редакцию (as-is Q5, Q18 уже это показывают без модели); проверка ND6 не знает, какая редакция «правильная» |
| Хранить только `current` | Q5 и любые `ED-CO` становятся неотвечаемыми; кейс требует исторических редакций документов компании |
| Граф знаний редакций (SAT-Graph) | идея та же, но на 8 документах компании интервалы в JSON достаточны; граф в продакшене (02-architecture/03 §7) |

## 6. На что влияет
Статусы: `abstain(outdated_edition)`, `limited` + `law_edition_warning`, `limited` + `conditions[]` по ДС, флаг `edition_applied` (ТЗ §3.2) при применении не текущей редакции. Критерии: достоверность 25%, архитектура и работа с документами 20% (кейс выделяет работу с редакциями отдельно). UI: бейдж редакции на карточке источника, предупреждение `superseded` в просмотре документа (ND8).

## 8. Режимы отказа
| FM | Симптом | Деградация |
|---|---|---|
| FM-ND5-1 | у документа нет дат редакции (закрытая база) | `edition_status=unknown`; документ используется как `current` с пометкой в трассе |
| FM-ND5-2 | интервалы пересекаются | ошибка manifest, предупреждение; выбирается более поздняя редакция, ответ `limited` |
| FM-ND5-3 | S7 не извлёк дату | `current`; если вопрос явно о прошлом (прошедшее время + «тогда»), `missing` |

## 9. Риски и дефекты
D6, D13. Риск: вопросы с относительными датами («в прошлом году») требуют «сегодня»; для сабмита дата прогона неизвестна заранее, поэтому такие вопросы получают `missing` с просьбой назвать дату, а не угаданный год.
