# 08.05. Ревью тестов и eval: достаточность покрытия, слабые оракулы, golden

> Версия 1.0, 10.11.2026. Стратегия: [`../07-tests/00-strategy.md`](../07-tests/00-strategy.md); eval: [`../07-tests/04-eval-golden.md`](../07-tests/04-eval-golden.md). Общие правила: [`00-overview.md`](00-overview.md).

## 1. Зачем и кто
**Зачем.** Тест, который проходит при любом поведении, хуже отсутствия теста: он создаёт уверенность. As-is набор ядра это показывает: 10 тестов зелёные, а из 18 вопросов организатора все нужные пункты среди меток первых трёх цитат есть только у Q8 (у Q1 есть п. 3.2, но нет п. 3.1), Q12 цитирует не тот закон (D28, [`../07-tests/02-regression.md`](../07-tests/02-regression.md)). Ревью тестов проверяет **оракулы**, а не только наличие тестов.

**Кто.**
| Что | Ревьюер | Почему |
|---|---|---|
| UT/CN/CT/RG роли 1 | роль 3 | знает, что должно получаться на данных базы |
| UT/RG UI роли 2 | роль 1 (контракт), роль 3 (состояния) | |
| golden-кейсы роли 3 | роль 1 (воспроизводимость), второй человек читает каждый ED, PREM, ABS (R3.2) | автор кейса не должен быть единственным читателем |
| Отчёт eval перед сабмитом | роль 1 и роль 3 вместе | решение о сабмите |

## 2. Когда
Каждый PR с тестами; каждый новый golden-кейс (пакетами); каждый отчёт eval перед сабмитом; при снятии `xfail`.

## 3. Что смотреть и как
### 3.1. Оракул
Порядок вопросов к каждому тесту:
1. **Может ли тест упасть?** Мысленно подставить неверный ответ (другой пункт, другое число, `grounded` вместо `abstain`). Если тест пройдёт, оракул слабый.
2. **Проверяет ли тест запрещённое?** Для фактов нужны и `must_include`, и `must_not_include` (иначе ответ «по обеим редакциям» проходит).
3. **Проверяет ли тест то, что заявлено в названии?** As-is `test_organizer_rent_grounded` проходит при «450» **или** «аренд» в ответе (test_pipeline.py 77): второе условие верно для любого ответа про аренду.
4. **Пропускается ли честно?** As-is тесты на базе делают `return` при отсутствии папки (63, 70, 83, 95): в CI без данных они зелёные. Правильно `pytest.skip("причина")`.
5. **Проверяет ли тест содержание, а не только форму?** Оракул «статус `grounded` и у каждой цитаты есть `doc_id`» проходит на as-is Q12, где цитируется НК ст. 284 вместо ТК ст. 70 (артефакт [`../07-tests/artifacts/asis-d1f068c-lexical-run.md`](../07-tests/artifacts/asis-d1f068c-lexical-run.md)). Это ровно тип ошибки misgrounded: источник есть, но он не подтверждает ответ [S-49], [S-48]. Содержательный оракул сверяет `must_cite` (документ и пункт) и `must_not_include`, а для цитат считает precision в духе ALCE: подтверждает ли каждая цитата своё утверждение [S-41]. Ошибка в обратную сторону тоже ошибка: ложный `abstain` или `clarify` учит пользователя не доверять системе и бросать её (disuse из-за ложных тревог), а уверенный ответ с чужой цитатой учит доверять сверх меры (misuse) [S-139]. Поэтому у каждого семейства кейсов в `07-tests/04` есть и «должен ответить», и «должен отказаться».

### 3.2. Уровень
- Логика, которую можно проверить чистой функцией, проверяется UT, а не RG через LLM (детерминизм [S-75]).
- Граница между узлами без CT является пробелом ([`../07-tests/01-cascade.md`](../07-tests/01-cascade.md)).
- Живой LLM только в RG с меткой `live` и в EV, с повторами.

### 3.3. Достаточность покрытия
Не процент строк, а вопросы:
- У каждого инварианта узла (раздел «Инварианты» в `06-nodes`) есть тест?
- У каждого D-номера есть `RG-DEF-Dn`?
- У каждого требования R* есть строка в [`../07-tests/05-traceability.md`](../07-tests/05-traceability.md)?
- Каждая клетка матрицы S17 покрыта UT-DEC?
- Каждая граница дат и порогов (01.03.2025, 01.10.2024, «свыше 3 млн») покрыта с двух сторон?
Покрытие строк используется только как подсказка, где искать непокрытое.

### 3.4. Флаки
Google наблюдает около 1,5% флаки-прогонов, и большинство переходов «прошёл → упал» в CI связано с флаки-тестами [S-76]; при temperature 0 LLM даёт разные ответы [S-77]. Ревьюер проверяет: тест на FakeLLM детерминирован; тест с живой моделью в EV, а не в блокирующем CI; запретительные проверки не карантинятся.

### 3.5. Golden
- У каждого `must_include` есть `kb_quote` из базы.
- Эталон написан по тексту базы, а не по памяти о законе (в базе законы только частями: например, в 152-ФЗ только ст. 9, Q13).
- ABS-кейс проверен поиском по базе: ответа действительно нет.
- CLAR-кейс: неоднозначность по каталогу, а не по кавычкам.
- Кейс не дублирует формулировку демо-вопроса с заменой одного слова (не проверяет обобщение).
- `split` проставлен; holdout не виден роли 1.

### 3.6. Отчёт eval
- Указаны sha, `PROMPT_VERSION`, `kb_hash`, флаги.
- Три прогона, среднее и минимум; изменение меньше разброса не называется улучшением.
- Калибровка суррогатного судьи пройдена (04-eval §6 п. 5).
- Есть разбор трёх худших кейсов до узла.
- Смещения LLM-судьи учтены: перемена мест, длина [S-80].
Hamel Husain отдельно подчёркивает, что смотреть на сами данные (ответы, трассы) важнее агрегатов [S-91]: ревьюер открывает минимум пять ответов целиком.

## 4. На что влияет находка
| Находка | Уровень | Влияние |
|---|---|---|
| Оракул не может упасть | `blocking` | ложная уверенность, D28 |
| Нет `must_not_include` на INJ, ED, PREM | `blocking` | выдумка проходит в сабмит |
| Эталон без `kb_quote` | `blocking` | eval учит систему выдумывать |
| Отчёт без повторов | `blocking` для решения о сабмите | шум принимается за улучшение |
| Нет CT на новой границе | `issue` | |

## 5. Как фиксировать
Слабый оракул в существующем тесте фиксируется как D28 (подпункт) с исправлением в том же или следующем PR. Спорный golden-кейс: обсуждение по тексту базы, решение записывается в `notes` кейса.

## 6. Готово / не готово
Готово: каждый новый тест может упасть (проверено мутацией ответа или FakeLLM); запреты присутствуют; трассировка обновлена; отчёт eval полный.
Не готово: «тест проходит» как аргумент; `in {a, b}`; `return` вместо `skip`; живой LLM в блокирующем CI.

## 7. Частые ошибки
| Ошибка | Как правильно |
|---|---|
| Считать число тестов | читать оракулы |
| Принимать снапшот-тест ответа LLM | снапшот недетерминированного текста либо флаки, либо ничего не проверяет; проверять claims и статусы |
| Править ожидание golden под систему | ожидание меняет только роль 3 и только по тексту базы |
| Не смотреть на сами ответы | открыть пять ответов [S-91] |
| Верить суррогатному судье без калибровки | три контрольные пары |
