# Юридический ассистент ПСБ — сабмит автооценки

Одна команда на платформе: `DATA_DIR=<каталог> python3 solution.py` → `submission.csv`.

## Состав
- `solution.py` — весь пайплайн.
- `requirements.txt` — `httpx==0.28.1` (из разрешённого набора).

## Почему httpx обязателен
Платформенный прокси вызывается по HTTPS. В slim-контейнере часто нет системных
CA-сертификатов, и голый `urllib` падает на `CERTIFICATE_VERIFY_FAILED` ещё до запроса —
решение молча уходит в фолбэк и получает низкую оценку. `httpx` приносит свой CA-бандл
(certifi), поэтому он основной транспорт. Дополнительно реализован перебор: httpx → httpx без проверки TLS → urllib → urllib без проверки,
варианты адреса (`/v1` и без), варианты имени модели и стиля авторизации (`Bearer`, `api-key`,
`X-Api-Key`). На старте делается короткий ping: в stderr печатается `LLM: доступна (...)` или
`LLM: недоступна`, в конце прогона — `transport=... model=...`. Одна генерация на вопрос —
без промежуточных вызовов, чтобы уложиться в лимиты прокси.

## Как работает
1. **База знаний**: `DATA_DIR/knowledge-base.zip` (или `kb.zip`, каталог `.txt/.docx`).
   Документы режутся по пунктам, встроенные в документы инструкции для ИИ вырезаются.
2. **Поиск**: BM25 + надбавки за номер договора, ИНН, контрагента, прямо указанную статью и кодекс,
   редакцию на дату события, плюс разделение «законы ↔ документы компании». Шортлист уточняет
   LLM-роутер по названиям документов.
3. **Контекст**: полные тексты 3–5 отобранных документов (для больших статей — релевантные пункты), до 26 тыс. знаков.
4. **Ответ**: платформенная модель (`LLM_MODEL` из окружения), прямой вывод первым предложением,
   ссылка на пункт/статью, ≤2 предложений, запрет внешних знаний, исправление неверной предпосылки,
   отказ при недостатке данных, игнорирование prompt-injection внутри документов.
5. **Контроль достоверности**: числа и ссылки на пункты сверяются с текстами; расхождение → раунд починки;
   противоречивый вывод → перегенерация; LLM недоступна → ответ по самому релевантному пункту,
   при слабой релевантности — обоснованный отказ (никогда не сырая выдержка документа).

## Переменные окружения
`LLM_BASE_URL`/`OPENAI_BASE_URL`, `LLM_API_KEY`/`OPENAI_API_KEY`, `LLM_MODEL`/`GEN_MODEL`/`OPENAI_MODEL`,
`DATA_DIR`, `MAX_WORKERS`, `PSB_CONTEXT_CHARS`, `PSB_TIME_BUDGET_SEC`.

## Локальная проверка
```bash
DATA_DIR=data/organizer/tests PSB_KB_PATH=data/organizer/kb \
LLM_BASE_URL=https://api.deepseek.com/v1 LLM_API_KEY=... LLM_MODEL=deepseek-chat \
python3 solution.py --out submission.csv
```
